## 준비 (시연 전날)

1. 시연 PC에서 대시보드를 만든다.
   `bun scripts/build-dashboard.ts --config config/orgs/example/org.json` → `runs/example/dashboard/index.html`을 브라우저로 연다(서버 불필요). 탭을 "법령 개정 영향"에 맞춰 둔다.
2. 평가 게이트를 실행해 통과 화면을 확인한다: `bun scripts/eval-gates.ts` (24 통과 · 0 실패 · 1 보류)
3. 대비용 녹화 클립 1개: 결함을 심은 처리방침을 격리 감사자가 잡아내는 장면(30초 이내).
4. 표지의 팀명·발표자를 확정했는지 확인한다. 발표 자료: https://claude.ai/artifact/VQRWPLE2Y8MEGMnqjnekT8

## 예상 질문과 답

- **법률 자문인가?** 아닙니다. 모든 결과는 참고용이며 최종 판단은 정보보호실·법무가 합니다. 확정 알림은 도메인 전문가가 규칙을 검증한 뒤에만 나갑니다.
- **실제로 시간이 얼마나 줄어드나?** 아직 측정하지 않았습니다. 지금 말할 수 있는 실측은 범위 축소입니다. 이번 개정에서 98개 조문 단위 중 처리방침과 연결되는 5개만 사람이 보면 됩니다. 시간 절감은 정보보호실 시범 측정으로 확인하려고 하고, 그게 요청 사항 첫 번째입니다.
- **다른 회사 사이트를 긁어도 되나?** 처리방침은 법에 따라 공개되는 문서이고(개인정보 보호법 제30조제2항), robots.txt를 지키며 하루 1회만 받습니다. 원문은 저장소에 두지 않고 해시만 보관합니다.
- **숫자가 합성 데이터 기준 아닌가?** 맞습니다. 게이트와 지적 건수는 합성·골든 데이터 기준이고, 실제 처리방침에서는 낮아질 수 있습니다. 98 → 5는 실제 법령 개정 데이터로 잰 값입니다.
- **놓치는 경우는?** 개정 영향 점검은 바뀐 조문과 연결된 항목을 찾는 일이라, 보호책임자 연락처가 빠진 것 같은 현재 결함은 현행 점검이 잡습니다. 두 기능을 같이 돌리는 이유입니다.
- **비용은?** 처리방침 1건 모델 점검이 정가 환산 약 0.3달러이고, Claude Code 구독으로 돌리면 별도 API 비용이 없습니다.
- **금융 계열사는?** 1차에서는 신용정보법 등 개정을 감시만 하고, 해당 조항은 모델에 보내지 않고 사람 검토로 넘깁니다.
