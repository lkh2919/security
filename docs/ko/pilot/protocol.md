# 정보보안 파일럿 프로토콜 (설계 C8)

상태: 파일럿. 표본이 작으며 검증된 벤치마크가 아닙니다. 영문본: `docs/pilot/protocol.md`.

## 1. 목적

수치를 지어내지 않고 업무 효과성을 측정합니다. 정보보안 검토자가 (a) 계열사 개인정보처리방침을 규칙에 맞춰 점검하는 데, (b) 법령 개정이 방침에 미치는 영향을 평가하는 데 걸리는 실제 소요 시간(분)을 기존 수작업 방식과 에이전트 지원 방식(에이전트 결과에 대한 사람의 검증 포함)으로 비교합니다. 또한 전문가 키(정답표) 대비 각 방식이 놓치거나 잘못 지적한 사항의 수를 비교합니다.

## 2. 참여자

- 정보보안 검토자 2~3명: R1, R2, (R3)로만 표기합니다. 모든 파일에 실명을 쓰지 않습니다.
- 전문가 키를 privacy-domain-expert 에이전트와 함께 작성하는 선임 검토자 1명(K1). K1은 시간 측정 대상 검토자를 겸하지 않는 것이 원칙입니다. 불가피하면 K1이 키를 만든 항목은 측정하지 않으며, 결과에 이를 명시합니다.

## 3. 항목 (총 8개)

방침 점검(task_type `policy_check`): `kb/jurisdictions/kr/monitor/peers/peer-registry.json`의 `groups[].lotte`에서 그룹별로 1~2개씩 고른 롯데 수집 방침 6건.

| 항목 | 레지스트리 id | 그룹 |
|------|---------------|------|
| P1 | lotte-wellfood-privacy | food (식품) |
| P2 | lotte-department-store-privacy | retail (유통) |
| P3 | lotte-mart-privacy | retail (유통) |
| P4 | lotte-castle-privacy | chem_build_mfg (화학·건설·제조) |
| P5 | lotte-hotel-privacy | tour_service (관광·서비스) |
| P6 | lpoint-privacy | finance (금융·멤버십; 금융 고유 법령은 범위 밖, 개인정보 보호법과 정보통신망법 점검만 키에 포함) |

개정 영향(task_type `amendment_impact`): 어떤 방침의 어떤 조항에 조치가 필요한지 판단합니다.

| 항목 | 개정 | 범위 |
|------|------|------|
| A1 | 개인정보 보호법 제21445호 (2026-09-11 시행) | 방침 P1~P6 |
| A2 | 정보통신망법 제21988호 (2026-10-02 시행) | 방침 P1~P6 |

모든 시트의 `item_id`는 P 항목은 레지스트리 id, A 항목은 `amend-21445`, `amend-21988`을 사용합니다.

## 4. 시행 방식(arm)

- **manual**: 검토자의 평소 방식(평소 도구, 체크리스트, 검색). 에이전트 결과는 보이지 않습니다.
- **agent**: 검토자는 항목별 에이전트 보고서(인용문과 위치 포함)를 받아 방침 원문과 대조 검증하고, 틀린 지적은 고치고 빠진 지적은 추가합니다. 점수는 검증 후 최종 목록으로 매깁니다. 시간에는 보고서 읽기와 모든 검증이 포함됩니다.

## 5. 상쇄(counterbalancing)

항목을 S1 = {P1, P3, P5, A1}, S2 = {P2, P4, P6, A2}로 나눕니다. 같은 항목을 두 방식으로 하는 검토자는 없습니다(기억 효과 방지).

| 검토자 | S1 | S2 | 순서 |
|--------|----|----|------|
| R1 | manual | agent | 수작업 세트 먼저 |
| R2 | agent | manual | 에이전트 세트 먼저 |
| R3 (있는 경우) | manual | agent | 에이전트 세트 먼저 |

검토자가 2명이면 각 항목은 한 방식으로 한 명만 측정하므로 항목별 짝비교가 되지 않습니다. 결과에 이를 명시합니다. 에이전트는 파일럿 전에 설정을 고정하고 항목당 한 번만 실행하며 그 `usage.jsonl`을 보관합니다.

## 6. 시간 측정 규칙

- 실제 경과 시간(wall clock), 현지 시각 HH:MM, 검토자(또는 관찰자)가 `timing-sheet.csv`에 기록합니다.
- 시작: 항목 자료를 열어 읽기 시작한 순간(manual), 또는 에이전트 보고서를 연 순간(agent).
- 종료: 해당 항목의 최종 지적 목록을 제출한 순간.
- 휴식(자리 비움, 통화, 다른 업무)은 `breaks_minutes`에 적고 제외합니다. `minutes = 종료 - 시작 - breaks_minutes`.
- 준비(도구 설치, 설명)와 이 프로토콜 읽는 시간은 측정하지 않습니다.
- 한 번에 한 항목만, 멀티태스킹 금지. 30분 넘게 중단되면 notes에 표시하고 중앙값 계산에서 제외하며 따로 나열합니다.

## 7. 지적 사항(finding)의 기준

하나의 지적 = 한 방침의 한 조항에 있는 하나의 구별되는 문제(개정 영향 과제는 개정 때문에 변경이 필요한 방침 조항 하나)이며, 조항 위치와 짧은 원문 인용을 포함합니다. 같은 문제가 여러 조항에 반복되면 조항마다 하나로 셉니다. 문체 선호나 방침만으로 답할 수 없는 사실 확인 질문은 키에서 심각도 `confirm`으로 넣은 경우에만 지적으로 인정합니다. 심각도: critical, high, medium, low, confirm. 검토자도 심각도를 적지만 키와의 일치 판단은 심각도가 아니라 조항과 문제 내용으로 합니다.

## 8. 재작업 시간

재작업 = 제출 후 선임 검토자 또는 키 대조에서 틀리거나 불완전하다고 판정되어 지적을 수정하는 데 쓴 시간, 또는(agent) 틀린 것으로 판정된 에이전트 결과를 고치는 데 쓴 시간. `notes`에 `rework=NN`으로 적고 따로 보고합니다. `minutes`에 몰래 합산하지 않으며, "분 + 재작업"을 별도 열로 보고합니다.

## 9. 전문가 키

- 항목별로 K1과 privacy-domain-expert 에이전트(모델 `opus`)가 작성하며, 누구도 에이전트 결과를 보기 전, 측정 세션 채점 전에 완료합니다.
- K1이 모든 키 행을 검토합니다. 이견은 K1이 정리하고 `notes`에 기록합니다.
- 파일: `expert-key-template.csv`를 복사해 `expert-key.csv`로 사용합니다. 인용문은 짧게(25단어 이하).
- 채점 전에 키를 동결하고 일시를 기록합니다. 동결 후 추가분은 "동결 후 추가"로 따로 보고합니다.

## 10. 분석

- 항목·방식별: 소요 분, 지적 수. 방식별과 과제 유형별: 항목 간 소요 분의 중앙값과 범위(최소~최대).
- 누락 = 키에는 있으나 최종 목록에 없는 지적. 오류 = 방침 원문으로 뒷받침되지 않거나 키와 모순되는 지적(K1이 판정).
- 모든 수치 옆에 n(검토자, 항목, 측정 세션 수)을 적고 "파일럿"이라고 표기합니다.
- 작은 표본의 평균을 대표값처럼 제시하지 않으며 유의성 주장을 하지 않습니다.
- 외삽(연간 시간, 계열사별)은 명시한 가정이 있을 때만 합니다. 가정은 팀 자체의 방침 수와 개정 빈도(팀이 제공)이며 가정임을 표시합니다.
- 비용은 실행의 `usage.jsonl`(정가 USD)에서만 가져옵니다. 팀이 단가를 제공하지 않으면 검토자 시간을 금액으로 환산하지 않으며, 제공하더라도 가정으로 표시합니다.

## 11. 개인정보와 보관

- 로그, 시트, 메모, 인용문에 개인정보 금지: 이름, 이메일, 전화번호, 사번 불가. 검토자는 R1~R3만 사용합니다. 수집한 방침에 공개된 담당자 연락처가 있을 수 있으므로 시트에 옮기지 않습니다.
- 파일은 내부(저장소 또는 내부 공유)에만 둡니다. 파일럿 보고서는 외부에 공개하지 않고, 슬라이드에는 집계 수치만 사용합니다.
- 파일럿 파일을 커밋하기 전에 `bun scripts/pii-scan.ts`를 실행합니다.
